# Changelog

All notable changes to Flagstaff are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) (pre-1.0: minor versions may break).

## [Unreleased]

## [0.3.0-alpha.2] - 2026-10-27

First published release; earlier versions below were not published.

### Added

- **Generic elements.** A PascalCase element name is a WinUI type (`Expander Header: "Advanced" { ... }`, `TabView`, `SplitView`, `MenuFlyout`), written in the universal element form: PascalCase keys are XAML properties, labels and string children are content, a positional `vm.X` binds the input property, `-> vm.XCommand` / `-> navigate(View)` work where the type has `Command` / `Click`, and keywords and generic elements nest both ways (FS1030–FS1032, FS1035, FS2014; FS4001 when a keyword exists).
- **Control manifest.** `winui-manifest.json`, generated by `tools/ManifestGen` from the Windows App SDK metadata (types, properties, CLR types, content properties, events, enum members), plus the hand-curated `overlay.json` (two-way input properties, keyword equivalents, value shapes, attached-property locality, reference properties). Bindings get their mode and ViewModel members their type from it.
- **Third-party controls:** `use "<assembly namespace>" as prefix;` and `prefix.Type` elements (FS1036; FS4002 for types outside the manifest).
- **Property elements and pass-through on keywords:** `Margin:`, `Style:`, `AutomationProperties.*`, and other XAML props land on each keyword's documented root tag; `Flyout:`, `ContextFlyout:` (row-level on `table`/`list`), and `KeyboardAccelerators:` as `Key: Type { ... }` / `Key: { ... }`, in the header or as lines in the block (FS1033 where a keyword cannot carry them yet).
- **Locality rule:** `Grid.Row`/`Column`/`RowSpan`/`ColumnSpan` only on direct children of a generic `Grid` and checked against its definitions (FS1038); `ref(Name)` / `ref(Name).Member` for every element reference, resolved against `name:` declarations (FS1039, FS1040, FS1042); an allowlist for attached properties (FS1037, FS1041).
- **Events:** `on Event -> vm.XCommand | navigate(View) | cancel` on any element, with typed code-behind handlers; `(item)` from a row, a `SelectionChanged`, or an `ItemClick`; `on ItemClick` sets `IsItemClickEnabled` (FS1034, FS1043, FS2015).
- **Resources and states:** `Page.Resources: { ... }` with `key:`, implicit and keyed `Style TargetType: T { Setter Property: P Value: V; }` (setters checked against the target type), `BasedOn:`, `VisualStateManager.VisualStateGroups:` with `AdaptiveTrigger` and `Setter Target: ref(X).Prop`, and `Storyboard key: ... { DoubleAnimation Storyboard.TargetName: ref(X) ... }` (FS1044, FS1045).
- **Value forms:** `theme(Key)`, `resource(Key)` (FS3010 for unknown keys), `ref(Name)`, `load: load(vm.X)` (`x:Load`), `key:` (`x:Key`), `uid:` (`x:Uid`); bare enum members, named colors, and `#argb` colors.
- **Escape ratio.** `flagstaff check`/`compile` print the share of `.flag` lines still in `xaml { }`, keyword vs generic element counts, and why each escape block still needs XAML (`stats` in JSON); `check --stats-only`; FS3011 for an escape block that is expressible as a generic element.
- `LANG.md` sections Generic Elements, Pass-Through Props, Locality Rules, Events, and Resources and States.
- **The generated contract.** Generated `*ViewModel.g.cs`, `*View.xaml.cs`, and item-type `T.g.cs` files start with a comment listing what they declare (properties with their type and the `.flag` usage that typed them, commands, the `On*Async` delegates to implement, the page constructors) and what the hand-written partial must not redeclare. `flagstaff check --format json` and `flagstaff stubs` expose the same data (`contract`, `itemTypes`; one line per ViewModel in `stubs` text output).
- **Contract hints on `flagstaff build`.** C# errors in the hand-written half against generated members get a hint naming the member, the `.flag` line it comes from, and the fix: re-declared properties/fields/commands (CS0102, CS0756), a page constructor (CS0111), `partial` methods the generator never declared or that are missing (CS0759, CS8795), a `string`-inferred property used as a number (CS0029, CS0266, CS0019, CS1503: add `format: number`), item types (CS0260 missing `partial`, CS1061/CS0117 unbound members, CS0246/CS0104 namespace), and ViewModel names used in a page partial (CS0103); WMC0011 unknown members (usually from `xaml { }`) get the manifest's suggestion (`Header` → `Title` on `MenuBarItem`). Hints appear in text output and in the JSON `hint` field.
- FS1048: an `icon:` that names no WinUI `Symbol` member is an error at the `.flag` line with the closest member (`previous-track` → `previous`, `settings` → `setting`), instead of a warning on the generated XAML (FS3003 now covers `xaml { }` only).
- `text` accepts `bold`, like `line`.
- LANG.md "The hand-written half" (also in AGENTS.md and the agent templates): what the generator owns, what not to redeclare, page constructors, delegates from `flagstaff stubs`, partial item types.
- **The generator skips what your C# already declares** (FS2016 warning, never a build failure): the CLI scans the project's hand-written partials (Roslyn, syntax only) before `check`, `compile`, `build`, `watch`, and the MSBuild compile. A ViewModel property or `[ObservableProperty]` field, a `[RelayCommand]`, a page constructor, a page `ViewModel`, or an item property declared by hand is not generated; an `On{X}Async` written as `public partial` gets a `public` declaration, a non-partial one is called directly. A `partial On{X}Async` no command declares gets a declaration (FS2017) instead of CS0759. `stubs` adds no delegate for a command you declared.
- **`partial void OnViewCreated()`** on every generated page, called once at the end of the generated constructor (after `InitializeComponent` and the ViewModel wiring): the place for page setup. A hand-written page constructor replaces the generated one instead of failing with CS0111.
- **`Generated/GlobalUsings.g.cs`**: `global using` for `Microsoft.UI`, `Microsoft.UI.Xaml.*` (controls, data, input, media, navigation), `Microsoft.UI.Input`/`Dispatching`, `Windows.Foundation`, `Windows.Graphics.Imaging`, `Windows.Storage.Pickers`, CommunityToolkit, `<App>.ViewModels`, and `Color = Windows.UI.Color`, so page and ViewModel partials need no `using` for them.
- Contract hints for CS8799 (partial method accessibility), CS0111 on a generated page method (`OnViewLoaded`), CS1061 for a handler named in `xaml { }` but not written, and CS1061 on a `DateTimeOffset?` (datepicker) used as a `DateTime`; CS0260 on a class Flagstaff does not generate is no longer described as generated; `.flag` paths in hints are relative to the project.
- **Your declared type wins.** A ViewModel or item property your partial declares with another type than the `.flag` infers keeps that type in everything generated about it: condition functions (`When_n(long count)`, `bool?` compared with `true`, an enum compared with a string by name), the badge control, row conditions, the contract (header, `check` JSON `inferredType`, `stubs`) and build hints; FS2016 names both types. A type that cannot work with the usage (a `checkbox` on a `string`, `format: currency` on a `bool`, a `number` on a `decimal`, `of Order` over another element type, a condition the type cannot satisfy) is the new error **FS2018**, naming the usage, both types, and the fix.
- **Delegate near misses.** When your only `On{X}Async` has another parameter list than its command: one without parameters for a row command is declared so (the command drops the row), one taking the row as `T?`/`object` is declared with that type, a `partial void` one is declared `void` and called without `await` (was CS8817); any other (a parameter where the command passes no row, another row type, two or more parameters) is the new error **FS2019** naming the generated signature and `-> vm.X(item)`, instead of FS2017 plus CS8795.
- Build hints for CS8817, CS8799/CS0759 on CommunityToolkit `On{Prop}Changed` hooks (no access modifier, the property's type), CS8795 with another parameter list, and WinUI 3 types in C#: CS0246/CS0234 on `InkCanvas`, `InkPresenter`, `Windows.UI.Input.Inking`, `MediaElement`, `WebView` give FS1030's replacement; shapes (`Polyline`) the `using Microsoft.UI.Xaml.Shapes;` (not global: `Path`); `Windows.UI.Xaml.*` the `Microsoft.UI.Xaml` namespace; `FileAccessMode`, `VirtualKey` and other types of left-out namespaces their `using`; CS0115 on `OnPointerPressed` in a `Canvas` subclass the event subscription.
- FS3011's hint writes the `xaml { }` block as the generic element to use (`MenuBar { MenuBarItem Title: "File" { MenuFlyoutItem Text: "New" on Click -> vm.NewCommand; ... } }`), abridged, and names the keyword when the root type has one.

### Changed

- The preference order is **keyword > generic element > `xaml { }`**; `xaml { }` is for what the compiler has not learned yet (control templates, other markup extensions), and LANG.md, README, and the agent assets say so.
- FS1023 counts `on Click`, a `Flyout:`, and a `link`'s `NavigateUri:` as a button's action.
- `docs/grammar.ebnf` covers the 0.3 syntax: bare names, property lines, `on` lines in blocks, `use`, and value forms.
- Clearer diagnostics for common mistakes: FS1051 for props on `xaml` (`xaml fill { }`) says to wrap the escape (`stack fill { xaml { ... } }`); FS1030 for UWP-only controls (`InkCanvas`, `InkToolbar*`, `MediaElement`, `WebView`, `CaptureElement`, `SearchBox`, `SettingsFlyout`) names the WinUI 3 replacement instead of suggesting a third-party `use`; FS1000 for `when`/`enabled` written as an element shows where the clause goes; FS1031 suggests common XAML-name synonyms first (`Header` → `Title` on `MenuBarItem`, `Text` → `Label`/`Content`, `Content` → `Text`, `Items` → `ItemsSource`, `Min` → `Minimum`); FS1032 on an `Icon:` suggests a `Symbol` member.
- LANG.md's `stat` section states that `stat` without `format:` binds a `string` and shows `format: number(0)` for counts.
- FS3002 no longer rejects `FontIcon` (it exists in WinUI 3 and the generic tier accepts it); it now flags only a `FontIcon` without `Glyph`, which renders nothing.

## [0.2.0-alpha.1] - 2026-10-26

### Added

- **Diagnostics.** Coded diagnostics in MSBuild format with hints, `path(line,col): error FS1001: message [hint: ...]`, in ranges FS1000–1099 (parse, schema, layout, overlays), FS2000–2099 (semantic and type), and FS3000–3099 (XAML lint). Unknown keywords and properties get "did you mean" suggestions. The full table is in `LANG.md`.
- **Multi-file compilation with error recovery.** A file with errors generates nothing while the other files still compile; unknown keywords are skipped and reported instead of stopping the parse.
- **Keyword schema.** `ElementSchema` is the single source of truth for keywords, props, flags, and enum values, extensible through partial registration files.
- **Conditions.** `when(...)` and `enabled(...)` with `!`, `&&`, `||`, parentheses, and typed comparisons against `vm.X`, `item.X`, and literals (including `null`), compiled into static `When_n`/`Enabled_n` functions on the page.
- **Universal props:** `width: auto|N|*|N*`, `span:`, `fill`, `align:`, `tooltip:`, `name:`; input props `placeholder:`, `hint:`, `readonly`, `min:`/`max:`/`step:`; `button variant: primary|danger`. Props with no effect where they are written are reported (FS1002, FS1012).
- **Layout:** the first top-level `toolbar` is pinned above the scrolling body; `fill` gives one child the remaining height (FS1010, FS1013); `row cols: N` with `span:`, child widths, and `wrap` (FS1011); `cards` wrap with `span:`; `split` column ratios from child widths; `heading vm.X`.
- **Lists:** `list items: vm.X of T { ... }` with row templates of ordinary elements bound with `item.X` (scope checked, FS2005).
- **Tables:** row actions (`button "Edit" -> vm.EditCommand(item);`), row click (`-> vm.OpenCommand(item)` or `-> navigate(View)`), `col width:`, `format: number(N)`, and `empty "..."` states for tables and lists (FS2011, FS2012).
- **Commands with the row as argument:** `-> vm.EditCommand(item)` generates `OnEditAsync(T item)` (FS1052, FS2007).
- **Select:** `options: ["A", "B"]` (string items) next to `options: 1..9`, and `items: vm.X of T display: item.Name` (FS2013).
- **Item type registry:** one `T.g.cs` per item type for the whole project, with properties collected from every `table`, `list`, `select`, and condition usage (FS2010 on conflicts).
- **Overlays:** `dialog` modals; `confirm ... -> vm.XCommand` sugar with generated OK and `Cancel{Flag}Command` buttons, `confirmLabel:`, and `variant: danger`; `toast ... duration: ms` auto-dismiss. `toast`, `confirm`, and `dialog` are hoisted into a page-level overlay layer (FS1020–FS1022, FS2003).
- **CLI** as a .NET tool (`Flagstaff.CLI`): `init`, `check`, `compile`, `stubs`, `build`, `run`, `watch`, `new view`, `doctor`, `spec`, with `--format json` output and stable exit codes. `spec` prints the embedded `LANG.md` or one section of it.
- `Flagstaff` NuGet package with MSBuild targets that compile `Flags/` to `Generated/` before XAML compilation. `Flagstaff.Stdlib` styles (now including table, list, empty-state, dialog, danger-button, and stat-variant styles) are included transitively.
- `samples/TaskTrack` sample app.
- `LANG.md` rewritten as the complete 0.2 reference, with drift tests that compile every example and check that every keyword, prop, and diagnostic code is documented. `docs/grammar.ebnf` matches the parser.
- Agent assets: `AGENTS.md` and `llms.txt`; `flagstaff init --agent claude|cursor` adds `AGENTS.md` plus a `CLAUDE.md` and a Claude Code skill, or a Cursor rule, to new apps.
- Contributor docs, issue and PR templates, and `docs/building.md`.
- `button "Cancel" -> cancel;` inside a `dialog`/`confirm` binds the generated `Cancel{Flag}Command` (FS1024 elsewhere).
- FS1023 (warning): a `button`, `filePicker`, or `link` without `->`.
- `partial void OnAppStarting(List<Func<Task>> steps)`: async startup steps, awaited before the main window is created.
- `link` inside a view navigates (`-> View`) or runs a command (`-> vm.XCommand`); `icon:` on `button`, `filePicker`, and `link`.
- `select` accepts `placeholder:`, `hint:`, `tooltip:`, `align:`, `name:`, and a pixel `width:`.
- Row-action buttons accept `variant:`, `icon:`, and the universal props.

### Changed

- `onload -> vm.Load;` generates a `LoadCommand` that delegates to `OnLoadAsync()`. The legacy `onload -> vm.LoadAsync;` still works but warns with FS2006.
- Commands delegate to C# extended partial methods (`private partial Task OnSaveAsync();`). You implement them as `private partial async Task OnSaveAsync() { ... }`, and the C# compiler checks the signature.
- Generated C# files start with `#nullable enable`.
- The page root is a `Grid` named `FlagstaffPage` (pinned toolbar row plus body row), so templates can reach page-level commands.
- `confirm` is a hoisted modal instead of an inline panel; a `confirm` needs either `->` or its own buttons.
- Type inference tracks confidence. Explicit usages win over comparisons, and incompatible types are reported as FS2004.
- Item types are emitted once per project instead of once per view.
- `README.md` was rewritten. The build notes moved to `docs/building.md`.
- `OnLaunched` is async; `OnAppLaunched()` still runs after the window is activated.
- `-> vm.Save` and `-> vm.SaveCommand` are the same command.
- `progress vm.X` infers `double`; `format:` (including `number(N)`) applies on `stat`, `line`, and bound `text`.
- Unquoted star widths (`width: 2*`) work on `col`, like on `row`/`split`/`cards` children.
- `textbox`/`textarea` update the ViewModel on every keystroke.
- Item bindings (`item.X`) are OneTime; item types stay plain classes (replace a row to update it).

### Fixed

- Unknown keywords, props, and enum values are errors instead of being silently ignored or emitted as comments.
- Generated C# no longer produces CS8669 warnings about nullable annotations outside a `#nullable` context.
- `onload` errors are no longer swallowed: the `Loaded` handler logs them and re-throws in DEBUG builds.
- Hoisted overlays (`toast`, `confirm`, `dialog`) no longer take a row, column, or cell in their container.
- A row action with `when()` keeps its column width, so header and rows stay aligned.
- Generated output no longer depends on the source path prefix.

## [0.1.0] - 2026-05-03

The first release: the generated XAML and C# build without hand edits, and the only hand-written code is business logic in partial classes.

### Added

- The `.flag` language: `app` (theme, `nav top|side`), `view`, layout (`row`, `column`, `stack`, `split`, `group`, `toolbar`, `card`, `cards`), display (`heading`, `text`, `stat`, `badge`, `summary`/`line`, `image`, `progress`, `spinner`, `separator`), inputs (`textbox`, `textarea`, `number`, `select`, `checkbox`, `radio`, `toggle`, `datepicker`, `filePicker`), `button` with commands or `navigate(View)`, `table` with `col`, `alert`, `toast`, `confirm`, and the `xaml { }` escape hatch.
- Type inference for ViewModel members from usage and `format:` (`currency`, `date`, `percent`, `number`).
- ViewModel partials with `[ObservableProperty]` and `[RelayCommand]` async commands that delegate to `On{Name}Async()`.
- Item type generation (`T.g.cs`) from `table ... of T` columns.
- Table row selection (`selected:`) and dynamic `select items:` (with `of T`).
- `onload` handlers on pages.
- Navigation shell (`MainWindow`) with a frame-navigation handler. It selects the first item on load and guards navigation errors.
- Full `App.xaml` and `App.xaml.cs` generation: `XamlControlsResources`, the styles dictionary, converter registrations, DI with automatic ViewModel registration, `App.GetService<T>()`, a static `MainWindow`, and `partial void ConfigureServices(IServiceCollection)` / `partial void OnAppLaunched()` hooks.
- Generated converters (`BoolToVisibility`, `Currency`, `Percent`, `Date`) and a `Converters` helper.
- Theme: an `accent:` that produces the full `SystemAccentColor` Light/Dark family, `backdrop: mica|acrylic|none`, `titlebar: extended|default`, `font:`, and `styles:` (CLI `--styles-source` overrides it).
- View code-behind with a parameterless constructor (for `Frame.Navigate`) and a DI constructor.
- A post-generation XAML linter: well-formedness, `FontIcon` usage, unknown `Symbol` values, `Grid.Column` overflow, `ViewModel.` bindings inside templates, missing `x:DataType`, `Window.Resources`, duplicate `x:Name`, namespace mismatches, and unknown `StaticResource` keys.
- `Flagstaff.Stdlib` styles packaged as a WinUI class library with `Flagstaff.props`/`.targets`, which warn when building with Core MSBuild.

### Fixed

- The namespace is consistent across multi-file compiles, and `--namespace` applies everywhere, including `MainWindow`.
- Views emit a single root container.
- `DataTemplate` bindings strip the `item.` prefix and carry `x:DataType`.
- Toolbar right-hand items are grouped into one panel instead of overlapping.
- Bound `text` inside cards emits `x:Bind`.
- `when()` comparisons work, and `when()` is honored on `text`, `card`, `split`, `group`, and `select`.
- `select` ranges produce typed `int` items.
- `format:` is applied in table columns, including `date`.
- `badge` infers `string` by default. An `int` badge uses `InfoBadge`, which fixes a runtime crash.
- `SymbolIcon` is used instead of `FontIcon`, and `Window.Resources` (invalid in WinUI 3) is no longer emitted.
- `MainWindow` code-behind imports `Microsoft.UI.Xaml`, and `MainWindow.xaml` no longer needs a resources block.
- `confirm` form children stack above the button row.
